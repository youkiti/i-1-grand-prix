# 用語解説（Glossary of Terms）

| 用語 | 解説（高校生にもわかる説明） |
| :--- | :--- |
| **船荷証券（Bill of Lading / B/L）** | 貿易において、運送会社が荷主から荷物を受け取ったことを証明し、目的地の港で荷物を引き渡すことを約束した書類。荷物の引換券のような役割を持ちます。 |
| **電子船荷証券記録** | これまで紙で発行されていた船荷証券を、コンピュータ上のデータとして扱えるようにしたもの。法改正案における法律上の正式名称です。 |
| **裏書（Endorsement）** | 有価証券（小切手や船荷証券など）の裏面に名前を書いて、その権利を別の人に譲り渡す手続きのこと。 |
| **LC決済（Letter of Credit / 信用状）** | 輸入者が代金を支払えるか心配な場合に、銀行が支払いを保証する仕組み。この手続きの中で船荷証券が重要な役割を果たします。 |
| **MLETR（電子譲渡可能記録に関するモデル法）** | 国連の委員会が作った、電子的な貿易書類のルールに関する世界的なお手本（モデル法）。日本もこれに合わせた法整備を目指しています。 |
| **DX（デジタルトランスフォーメーション）** | デジタル技術を使って、業務の手順やビジネスの仕組みそのものをより良く変革すること。単なる電子化（ペーパーレス）を超えた意味で使われます。 |

# 1. パブリックコメントによる仮説の検証

審議会で前提とされた方向性のうち、パブリックコメントにおいてその妥当性が確認され、強く支持された論点は以下の通りです。

**1. 電子化による業務効率化とコスト削減への期待**
審議会では、電子化による利便性向上を前提に法制度設計が進められましたが、パブリックコメントにおいても、現場の実務担当者から具体的な業務削減効果や効率化への強い期待が示されました。

> 「10-15%程度の業務削減につながる。顧客も理解が進めば、すべての貿易書類が電子化できることにより、作成、準備、送付をすべて自動化・省力化する可能性が大いに出る」 [パブコメ: [d6f69127-cbab-4579-9a4e-792db1372923](https://depth-interview-ai.vercel.app/report/d6f69127-cbab-4579-9a4e-792db1372923)]

> 「印刷が簡素化されて良いです。その上、ペーパーレスで業務改善になります！残業代削減可能になります‼️」 [パブコメ: [8921fe45-3b99-4a73-a8f5-36580b494d21](https://depth-interview-ai.vercel.app/report/8921fe45-3b99-4a73-a8f5-36580b494d21)]

**2. 国際的な実務動向との整合性の重要性**
審議会資料では、MLETRや英国法などの国際動向を重視し、名称や定義を検討していました。パブリックコメントでも、国際規格への参入や国際標準への対応を求める意見があり、この方針は支持されています。

> 「国際規格に日本ははやく参入すべき。中核的役割をになえば日本にとっても不利な運用とならず、国際的に公平に運用すれば日本が不利な立場におかれないという経済安全保障メリットがある。」 [パブコメ: [11b917fc-e64b-4d4a-a520-6af11586a56a](https://depth-interview-ai.vercel.app/report/11b917fc-e64b-4d4a-a520-6af11586a56a)]

> 「海外法制の動向を見ると、MLETR やシンガポール法では“electro transferable record”、イギリスのLaw Commissionの２０２２年３月１５日の「電子取引文書－報告書及び草案」...では“electronic trade document”といった用語が用いられており、いずれも“magnetic”という単語は用いられていない。」 [船荷証券に関する規定等の見直しに関する中間試案の補足説明](https://www.moj.go.jp/content/001394827.pdf)

**3. 紙の船荷証券との併用・移行期間の必要性**
審議会では「紙の船荷証券の利用継続は相当」との見解で一致していましたが、パブリックコメントにおいても、システムの並行運用や十分な移行期間を求める声が多く、紙を即座に廃止せず併用を認める方針は実務の実態に即していることが確認されました。

> 「システムの並行運用がいいかもしれません、リスク分散ですね。肉は切られても骨は絶やさない、という考え方です」 [パブコメ: [bd685d57-adf0-4acb-9495-51964148e3de](https://depth-interview-ai.vercel.app/report/bd685d57-adf0-4acb-9495-51964148e3de)]

> 「まずはマニュアル作りをし、誰も取り残さずに、この電子化に順応できるようにする必要がある。そのあいだには移行期間を設けるなど必要ですね。」 [パブコメ: [adf3dfa2-3cb2-4a99-9f3e-11d8872eab3f](https://depth-interview-ai.vercel.app/report/adf3dfa2-3cb2-4a99-9f3e-11d8872eab3f)]

# 2. パブリックコメントによる反対・懸念の顕在化

審議会での議論に対し、パブリックコメントにおいて懸念が示された点や、実務的な課題として顕在化した論点は以下の通りです。

**1. 中小企業やITリテラシーへの配慮不足への懸念**
審議会資料では、技術要件を柔軟にする方針などは示されていますが、具体的な導入支援策についての議論は限定的でした。パブリックコメントでは、中小企業が取り残されるリスクや、教育コストへの懸念が多数寄せられています。

> 「導入支援と移行期間の一定確保はしてあげないと、中小企業の負担が重くなってしまうので、配慮してあげるべきだと思います」 [パブコメ: [c8853765-bb12-4aa0-883b-e4fe9149fd00](https://depth-interview-ai.vercel.app/report/c8853765-bb12-4aa0-883b-e4fe9149fd00)]

> 「設備よりも教育にコストがかかる。」 [パブコメ: [a8dec2b9-8408-40d6-91b9-e310bea82635](https://depth-interview-ai.vercel.app/report/a8dec2b9-8408-40d6-91b9-e310bea82635)]

**2. 関連システム（銀行決済・通関等）との連携に対する不安**
審議会では主に船荷証券そのものの法的位置付け（物権的効力か否か等）に焦点が当てられていましたが、パブリックコメントでは、LC（信用状）決済や通関などの周辺実務とシームレスに連携できるかどうかが、実用化の鍵であるとの指摘がなされています。

> 「LC決済にて船積みを進める荷主も多く、その部分を電子でもできるように進めてくれるのでしょうか？」 [パブコメ: [62c19431-5b4c-44fc-af79-a4d793cf1d17](https://depth-interview-ai.vercel.app/report/62c19431-5b4c-44fc-af79-a4d793cf1d17)]

> 「現状としては、船に証券以外にも原産地証明書など電子化ができていない書類も存在するので、それらはもうまとめてしっかりと電子的に処理ができるように、行政側のシステム化を強力に推進してほしいと思っています」 [パブコメ: [972e7aa0-cf81-4519-ae13-7d474d4fc164](https://depth-interview-ai.vercel.app/report/972e7aa0-cf81-4519-ae13-7d474d4fc164)]

**3. システムダウンや通信環境への懸念**
審議会資料では法的な権利移転の構成が中心でしたが、現場からは、航海中の船舶の通信環境やシステムダウン時の対応といった物理的・技術的な課題への懸念が示されています。

> 「ただし､航海中の船舶での通信帯域などの実用上の問題もあり得ると思うので､あくまで何も知らない人間としては賛成という程度です」 [パブコメ: [dada6e21-dd53-4301-936b-afef8045caef](https://depth-interview-ai.vercel.app/report/dada6e21-dd53-4301-936b-afef8045caef)]

> 「PCをそれほど触り慣れていない人とか、あまりセキュリティ等に詳しくない人が触ると、システム側の設計が悪いと何をしたらいいかみたいなところがあまりわからなくて、結構お金に関わる部分だと思うので、その点で不安になる方は多いのかなと思います。」 [パブコメ: [197f73c6-af2f-4280-8d41-091d584dc795](https://depth-interview-ai.vercel.app/report/197f73c6-af2f-4280-8d41-091d584dc795)]

# 3. 新たなインサイト・論点

審議会資料には現れていなかったものの、パブリックコメントによって新たに提起された重要な視点は以下の通りです。

**1. データの二次利用（AI活用）への期待**
単なるペーパーレス化にとどまらず、蓄積されたデータをAI解析等に活用することで、さらなる付加価値を生み出すことへの期待が示されました。これは法制度設計の枠を超えた、産業振興の視点です。

> 「業務の効率化には寄与しそうですよね。紙だと面倒ですし。ai friendlyなデータが蓄積されることに期待します。」 [パブコメ: [5e78d613-a600-4de8-8e0c-cde0868e9047](https://depth-interview-ai.vercel.app/report/5e78d613-a600-4de8-8e0c-cde0868e9047)]

**2. 労働力不足対策としてのDX**
少子高齢化に伴う労働人口の減少を見据え、人が行うべき判断業務と機械化すべき業務を切り分けるための手段として電子化を位置付ける意見がありました。

> 「管理する人員は少子化で減少することは決まっていますし、場所にとらわれず内容を確認できるインフラ整備的な意味合いでも物体での管理に依存する環境から脱却できる足場は作る必要があると思います。」 [パブコメ: [8a823a53-0ddc-4fe5-a126-6f657aa6fbac](https://depth-interview-ai.vercel.app/report/8a823a53-0ddc-4fe5-a126-6f657aa6fbac)]

> 「電子化できるものはすべて電子化し、人手を介する作業は極力なくしてほしい。人はものを判断をする仕事に注力してほしい」 [パブコメ: [ef6742d7-446d-4c63-b658-3b1165f73c75](https://depth-interview-ai.vercel.app/report/ef6742d7-446d-4c63-b658-3b1165f73c75)]

**3. 電子化コストの負担論**
電子化を行わないことによる社会的な非効率コストについて、反対者が負担すべきという強い意見も見られました。

> 「電子化しなければ人手が必要。その追加コストは電子化に反対する人たちだけで払うべき。」 [パブコメ: [3a715c2f-0a5c-48d2-a336-5d859bf93b97](https://depth-interview-ai.vercel.app/report/3a715c2f-0a5c-48d2-a336-5d859bf93b97)]

# 5. 今後の対応方針案（国会アクションカード形式）

## 5.1 まとめ

パブリックコメントでは、法的な権利構成よりも「実務的な効率化」「中小企業支援」「他システムとの連携」への関心が高いことが明らかになりました。国会審議においては、法案の成立を前提としつつ、その後の運用環境整備（予算、ガイドライン、インフラ）を確実にするためのアクションが有効です。

- **主要論点**: 中小企業・高齢者への導入支援、銀行・税関システムとの包括的連携、通信インフラ確保。
- **狙う成果**: デジタルデバイドの解消、実効性のある「貿易DX」の実現。
- **推奨コンボ**: カード2（委員会質疑） → カード1（賛成討論での要望） → カード3（質問主意書で詳細確認）

## 5.2 論点マップ

| 論点 | 何が問題か | だれに影響か | どのレイヤーで動くか |
| :--- | :--- | :--- | :--- |
| **導入支援** | 資金・人材不足の中小企業が対応できない | 中小輸出入業者、フォワーダー | 予算 / 監督強化 |
| **システム連携** | 船荷証券だけ電子化しても決済等が紙では効果半減 | 荷主、銀行、商社 | 政省令 / 監督強化 |
| **通信インフラ** | 船上などの通信環境が不安定な場合の法的安全性 | 海運会社、荷主 | 政省令 / 技術基準 |

## 5.3 推奨アクション（カード別）

### カード2: 国会の各種委員会での質疑・発言

- **ねらい**: 法案審議の場で、政府に対して周辺環境整備の具体策を問いただし、議事録に残すことで言質を取る。
- **使うべき論点**: 中小企業への導入支援、銀行システム（LC決済）やNACCS（輸出入・港湾関連情報処理システム）との連携スケジュール。
- **具体アクション**: 法務委員会または国土交通委員会において、「法案には賛成だが、現場からは中小企業の負担増を懸念する声が多い。具体的な支援策や移行期間のサポート体制はどうなっているか」と質問する。
- **期待アウトカム**: 政府から「中小企業への周知徹底や支援を行う」「関係省庁と連携してシステム接続を進める」といった答弁を引き出し、附帯決議への足がかりとする。
- **リスクと代替策**: 抽象的な答弁に終始する可能性があるため、パブコメの具体的な引用（「設備よりも教育にコストがかかる」等）を用いて迫る。

### カード1: 法律案・条約・予算に対する賛否の投票（附帯決議の活用）

- **ねらい**: 法案成立時に、政府が講ずべき措置として「デジタル弱者への配慮」や「システム連携」を明記させる。
- **使うべき論点**: パブコメで多数寄せられた「誰一人取り残さない」ための配慮、教育・研修の必要性。
- **具体アクション**: 委員会の採決時に、各派共同提案による附帯決議を提出する。内容は「中小規模事業者への十分な周知期間と支援を行うこと」「国際標準との整合性を確保しつつ、セキュリティ対策に万全を期すこと」など。
- **期待アウトカム**: 法律の条文には書かれない運用面での配慮義務を政府に課すことができる。
- **リスクと代替策**: 与野党の合意が必要。パブコメでの賛同意見が多いことを根拠に、党派を超えた課題であることを強調する。

### カード3: 質問主意書（政府に対する公式質問）

- **ねらい**: 委員会質疑で詰めきれなかった技術的・細目的な課題について、政府の公式見解を書面で確定させる。
- **使うべき論点**: 航海中の通信途絶時の法的扱いの詳細、AI活用を見据えたデータ標準化の方針。
- **具体アクション**: 「電子船荷証券記録の利用における通信環境の確保及びデータ利活用に関する質問主意書」を提出する。
- **期待アウトカム**: 政府内部での検討状況（未検討であれば検討のきっかけ）を明らかにできる。
- **リスクと代替策**: 回答作成に時間がかかる場合があるが、国会閉会中でも提出可能。

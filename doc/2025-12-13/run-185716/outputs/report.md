# 用語解説（Glossary of Terms）

| 用語 | 解説（高校生にもわかる説明） |
|------|------------------------------|
| **船荷証券 (B/L)** | 貿易で使われる「荷物の引換券」です。これを持っている人だけが港で荷物を受け取れる重要な書類で、お金と同じような価値を持ちます。 |
| **電子船荷証券記録 (EBL)** | 紙の船荷証券をデジタルデータにしたものです。パソコン上でやり取りできるため、郵送の手間や紛失のリスクが減ると期待されています。 |
| **MLETR (モデル法)** | 国連が作った「電子的な引換券」に関する法律の雛形です。世界中の国がこれに合わせて法律を作れば、国をまたぐ電子取引がスムーズになります。 |
| **機能的同等性** | 「紙」と「電子データ」の見た目は違っても、法律上は「同じ役割・同じ効力」として扱うという考え方です。 |
| **支配 (Control)** | 電子データは手で「持つ（占有する）」ことができないため、代わりにシステム上で「自分だけが使える状態」にすることを指す新しい法律用語です。 |
| **裏書 (Endorsement)** | 船荷証券の裏にサインをして、権利を別の人に譲り渡すことです。電子化された場合は、システム上で記録することで行います。 |
| **UCP600** | 銀行が関わる貿易決済（信用状取引）の国際的なルールのことです。電子船荷証券を使うには、このルールの対応も必要になります。 |

# 1. パブリックコメントによる仮説の検証

審議会での議論の方向性が、パブリックコメントによって実務的な観点から支持された点は以下の通りです。

**1. 国際的な調和とMLETR準拠の必要性**
審議会では、日本独自の規制（認証機関制度など）を設けず、国際的なモデル法（MLETR）や英国法などの「機能的同等性」アプローチを採用する方針が示されました。パブリックコメントでも、国際規格への準拠が強く求められており、この方向性が支持されています。

> 「MLETR、シンガポール法、Law Commission 草案がその記録の方法として磁気的方式が取られることを禁止している又は想定していないのか否かは定かではないものの、このような国際動向を踏まえれば、我が国における電子化された船荷証券の法律上の名称としても、無用な誤解を避ける趣旨で、「電磁的」という用語の使用を避けることが考えられる。」 [出典: doc_008]

> 「国際規格に積極的に参加すべきです。そのうえで以下を考慮すべきです。・国際的な互換性の確保・セキュリティ基準の明確化」 [パブコメ: 33867b26-a26f-491b-877b-65bdb51148b7]

> 「日本独自のシステムは無意味。つくるなら「世界共通（含む後進国）」にして。国際的な標準化に向けた取り組みや、後進国も含めた共通システムの構築に主導的な役割を果たすべきだ。」 [パブコメ: 6b907a94-6a9a-4209-a7b8-122deb9ec5f2]

**2. 電子化による業務効率化とコスト削減の期待**
審議会では、電子化の目的として流通性の付与や産業界のニーズへの対応が挙げられていました。パブリックコメントでは、紙の書類到着待ちによる貨物滞留（特に近隣国との貿易）の解消や、管理コスト削減への期待が具体的に示され、法改正の必要性が裏付けられています。

> 「船足の短い地域、例えば韓国向けなどは、現場書類より貨物の方が先に届いてしまっているので、電子化になれば、書類が遅れて通関ができないと言う。現在の問題が解決されると思う。」 [パブコメ: fc0f1f96-af44-4a56-bc05-b539824e9442]

> 「電子化することで、時間やお金を節減できて効率化しそう 書類の郵送がなくなり手続きが早くなる。いつでもどこでも手続きできる」 [パブコメ: 2822a875-746d-4fac-a96e-29bfc26aa97f]

**3. 公的機関による認証制度の不採用**
審議会では、国の認証を受けた機関のみが発行できるとする制度（韓国型）は採用せず、利用を阻害しない方針（英国型）が示されました。パブリックコメントでも「日本独自仕様」や「ガラパゴス化」を懸念する声があり、認証制度を不要とした判断は妥当であると考えられます。

> 「電磁的船荷証券記録は、紙の船荷証券と同様に、国際的に利用されるものであることが想定されるところ、国の認証を受けた機関による関与を必要的なものとしてしまうと、一部の国の立法例のように、かえって利用がされなくなるおそれがある。そこで、本報告書においては、国の認証を受けた機関による関与については特に規律を設けていない。」 [出典: doc_087]

> 「国際標準化された機構に則った仕組みが求められると思いますが、わが国独自仕様にこだわらないか心配。」 [パブコメ: 5bf4fb8d-e7c6-4f9c-a100-3b094cdd6de0]

# 2. パブリックコメントによる反対・懸念の顕在化

審議会での議論に対し、パブリックコメントで懸念や異論が示された点は以下の通りです。

**1. システムの信頼性・セキュリティに対する強い懸念**
審議会では、システムの「信頼性（Reliability）」を法律上の有効要件とはせず、訓示規定（努力義務）にとどめる方針（丙案）が優勢でした。これは有効要件化による取引の不安定さを避けるためです。しかし、パブリックコメントでは、サイバー攻撃やシステム障害に対する「鉄壁の対策」や「銀行並みのセキュリティ」を求める声が多数あり、法的な要件と利用者の期待値にギャップが存在します。

> 「電子船荷証券記録の技術的要件として、一般的な信頼性の要件をその有効要件として定めることはしないが、一般的な信頼性の要件について、例えば、次のような規定を設ける。電子船荷証券記録を発行する者、電子船荷証券記録に記録する者、電子船荷証券記録の支配を移転する者その他電子船荷証券記録に関する行為をする者は、〔法務省令で定める事項（注）を考慮し、〕信頼性のある手法を用い〔るように努め〕なければならない。」 [出典: doc_010]

> 「昨今、国際的な大企業を狙ったサイバー攻撃が頻発しています。紙媒体を廃止してしまうと、このような事態に対応できません。」 [パブコメ: 1dab198b-8eb4-4193-8d68-8dc10abdc510]

> 「電子データの本物確認、二重三重のバックアップ、改ざん防止、暗号機能の確保が可能か。また特定国の管理だけでなく国際的に信用できる体制でデータ管理しないと不正な目的をもった国であれば密輸や裏ルートでの輸出入が可能になってしまう。」 [パブコメ: 11b917fc-e64b-4d4a-a520-6af11586a56a]

**2. 紙と電子の転換（コンバージョン）とBCP（事業継続計画）**
審議会では、電子から紙への転換請求権を義務化せず、当事者の合意に委ねる（X案）方針が採用されました。パブリックコメントでも義務化への懸念は一部ありましたが、同時にシステム障害時や、電子化に対応していない国・地域との取引における「バックアップとしての紙」の重要性が指摘されています。法的な権利としての転換請求権は否定されましたが、実務上のBCPとしての転換手段の確保に対する不安は払拭されていません。

> 「これに対し、Ｘ案を支持するものとしては、①デジタルファーストの志向からすると紙の船荷証券への転換請求権は認めるべきではない、（中略）転換請求権を認めるまでの必要性に乏しいのではないか、」 [出典: doc_006]

> 「外国とのやり取りがあった場合は、心配がある。きっちりしている国だけではなく、賄賂、適当な制度を適当な人員で運営している国はあると思うので、そういう場合は紙に合わせる必要があるかもしれない。」 [パブコメ: 1488dc8d-02a7-4626-a9a8-6422d8ded5eb]

> 「現場では紙媒体と電子媒体の混在による一時的な混乱、システムの使いづらさ、海外の取引先に「難癖」をつけられるリスクなど。」 [パブコメ: 9144f8ed-8337-4bea-91ec-877bc0713d66]

# 3. 新たなインサイト・論点

審議会資料には明示されていなかったものの、パブリックコメントから新たに浮上した視点です。

**1. 具体的な技術的・文化的障壁への対応**
審議会では法制度設計が中心でしたが、パブリックコメントでは、名前に姓（Family Name）がない国（インドネシア等）や特殊文字の扱いなど、国際共通システムを構築する上での具体的なデータ仕様の課題が指摘されています。

> 「例えば、地名や人名の形式が違うこと。地名で言えば、表記が決まってない、とか、特殊文字が必要でPCで処理できない、とかがある。人名も、ミドルネームがあった場合、日本のシステムだとうまく表現できない。また、インドネシアでは、family nameがない名前が一般的で、そういうのだと表記が決まらない。」 [パブコメ: 1488dc8d-02a7-4626-a9a8-6422d8ded5eb]

**2. 経済安全保障の観点**
貿易データの管理主体や共有範囲について、経済安全保障上の懸念（仮想敵国とのデータ共有リスク等）が指摘されています。単なる商流の効率化だけでなく、データのガバナンスが国防上の課題として認識されています。

> 「やはり、貿易は仮想敵国などとも行う可能性もあり、そのような国などと歩調を合わし共に監視できるシステムの構築方法に関して検討する必要があるのではないかと考えます。」 [パブコメ: e0571baf-883a-4aa1-ba9a-045d935040bf]

**3. UCP600（信用状統一規則）への言及**
法制度だけでなく、銀行実務の国際ルールであるUCP600における電子B/Lの取り扱いを明確化すべきという具体的な要望が出されています。

> 「３）ICC荷為替信用状に関する統一規則及び慣習（UCP600)に、電子BLの取り扱いを明記すべき。これは絶対絶対必要！」 [パブコメ: 5e581146-cc79-40e5-8c4b-2ee1f79fd30d]

- **合意形成への示唆**: 法案としては丙案（訓示規定）で進めるとしても、政省令やガイドラインレベルで、具体的なセキュリティ基準やBCP（事業継続計画）の策定を強く推奨し、利用者の不安を払拭する必要があります。

# 5. 今後の対応方針案（国会アクションカード形式）

## 5.1 まとめ

- **主要論点**: 国際標準（MLETR）への完全準拠、システム障害・サイバー攻撃時のBCP確保、および実務上のデータ仕様の統一。
- **狙う成果**: 電子船荷証券法案の早期成立と、利用者が安心して使えるセキュリティ・BCPガイドラインの策定。
- **推奨コンボ**: **2. 委員会質疑**（セキュリティ・BCPの確認） → **1. 賛否の投票**（法案成立） → **3. 質問主意書**（国際標準化への継続的関与の確認）。

## 5.2 論点マップ

| 論点 | 何が問題か | だれに影響か | どのレイヤーで動くか |
| :--- | :--- | :--- | :--- |
| **システム信頼性** | 法的に「信頼性」を有効要件としないが、実務上のセキュリティ不安が大きい。 | 荷主、運送人、銀行 | 政省令・監督強化 |
| **国際相互運用性** | 日本独自のデータ仕様や文字コード制限が生まれると、海外で使えない。 | 輸出入企業 | 法律（運用）・国際連携 |
| **BCP（紙への回帰）** | サイバー攻撃やシステムダウン時に物流が止まるリスク。 | 物流業界、消費者 | 業界ガイドライン・監督 |

## 5.3 推奨アクション（カード別）

### カード2: 国会の各種委員会での質疑・発言

- **ねらい**: 法案審議（法務委員会等）において、政府の方針（認証不要、信頼性は訓示規定）を支持しつつ、実務上の不安（セキュリティ、BCP）に対する政府の認識と対応策を議事録に残す。
- **使うべき論点**:
    - パブコメで出た「サイバー攻撃への懸念」（Topic 003）。
    - 国際的なデータ仕様の整合性（Topic 001/003）。
- **具体アクション**:
    - 「信頼性」を有効要件としなかった理由を再確認し、その上で、システム提供者に対してどのようなセキュリティ基準を求めるのか（省令レベルでの担保）を問う。
    - 大規模なシステム障害が発生し、電子記録が利用不能になった場合の代替手段（紙への切り替え等）について、政府としての見解を問う。
- **期待アウトカム**: 法案の修正までは求めずとも、省令制定時や運用時のセキュリティ基準の明確化、BCPに関する政府見解の引き出し。
- **リスクと代替策**: セキュリティを強調しすぎると、過度な規制（日本独自仕様）を招くリスクがある。「国際基準（MLETRやISO）に則った上でのセキュリティ確保」という文脈を崩さないことが重要。

### カード3: 質問主意書（政府に対する公式質問）

- **ねらい**: 法成立後の国際的な連携や、銀行実務（UCP600）との整合性について、政府の取り組みを具体化させる。
- **使うべき論点**:
    - 経済安全保障上のデータ管理（Topic 003）。
    - 銀行ルール（UCP600）との整合性（Topic 001の新たな視点）。
- **具体アクション**:
    - 電子船荷証券のデータが特定の国（仮想敵国等）に不当に管理・監視されるリスクに対する政府の認識と対策を問う。
    - 電子船荷証券の普及に向け、ICC（国際商業会議所）等の国際機関とどのように連携し、UCP600等の民間ルールとの整合性を図るのか質問する。
- **期待アウトカム**: 経済安全保障の観点からのデータガバナンス方針の明確化。貿易金融円滑化への政府のコミットメント確認。
- **リスクと代替策**: 特になし。

## 5.4 追加で確認したい情報

1. **諸外国（特にシンガポール、英国）におけるBCPの実例**: システムダウン時に法的にどのような措置が取られているか、または契約実務でどう処理されているか。
2. **UCP600のeUCP（電子信用状統一規則）の普及状況**: 現状の銀行実務で電子B/Lがどの程度受け入れられているか。
3. **法務省令で定める予定の「信頼性を確保するための措置」の具体案**: セキュリティ要件として具体的に何（ISO27001等）を想定しているか。
